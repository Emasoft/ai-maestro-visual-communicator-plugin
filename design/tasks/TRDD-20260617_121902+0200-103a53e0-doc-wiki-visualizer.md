## The navigation shell (the shared layer — Phase 1)

`scripts/amvcp-docwiki.js`:
- **Hash-router**: `#/<type>/<id>` → show that page, hide others, update breadcrumb +
  active state. `onhashchange` drives it; initial load routes to `#/home` (an index).
- **Link interception**: any `[data-ve-navigate="<type>/<id>"]` (or in-wiki `<a>` whose
  href is an in-set doc) → `location.hash = …` (lets the browser record history).
- **Back/forward**: native (hash history). In-page ◀ ▶ buttons call `history.back()` /
  `history.forward()`. A **breadcrumb bar** (top, sticky) shows Home › … › current,
  each crumb clickable; reuse `breadcrumb-stack.md` styling.
- **Search box** (top bar): submits the query; the SPA shows a `#/search?q=…` results
  page whose HTML was pre-generated by the search script (Phase 4) and embedded, OR
  (live mode) injected by the agent after a memgrep run.
- All chrome themed from `--vc-*` (light + dark), `overflow:visible` (no inner scroll).

## Build pipeline + search (Phases 2-4)

- `scripts/amvcp-docwiki-build.py` — scan the target folders, parse frontmatter +
  cross-refs, render each doc to an embedded page, build the link graph + breadcrumb
  ancestry + the kanban index, emit ONE self-contained `<docset>.html` (runtime + CSS
  inlined). Fail-fast on a broken cross-ref (report it, don't silently drop).
- `scripts/amvcp-docwiki-search.py` — stdin = `memgrep recall --json` (or plain
  grep) output; stdout = the Wikipedia-style results-list HTML fragment (title +
  description snippet + `data-ve-navigate` link per hit). Claude pipes memgrep → this
  → gets HTML, ≈0 context tokens.
