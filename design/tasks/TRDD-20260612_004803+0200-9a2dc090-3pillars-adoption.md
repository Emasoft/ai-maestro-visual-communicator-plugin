## What was done

This TRDD records the adoption of the 3-pillars tasks system
(PRRD + TRDD + kanban) for the `ai-maestro-visual-communicator-plugin`
(amvcp), following the **depend-on-base** model: amvcp does NOT copy the
pillar scripts into its own tree — it ships only a dependency-free
resolver shim and resolves the base plugin's scripts at runtime.

1. **Resolver (depend-on-base).** Copied
   `resolve_pillar_scripts.sh` from `ai-maestro-plugin` into
   `scripts/prrd-trdd/resolve_pillar_scripts.sh` and made it executable.
   It prints the absolute path of the installed base plugin's pillar
   directory — via `$AI_MAESTRO_PRRD_SCRIPTS_DIR`, its own directory, or
   the highest installed `~/.claude/plugins/cache/*/ai-maestro-plugin/*/
   scripts/prrd-trdd` — never a hard-coded cache path.
2. **Bootstrap.** Ran `bootstrap_design.py` to create the design/ 4-zone
   model (`proposals/`, `tasks/`, `archived/`, `refused/`, plus
   `requirements/`). The pre-existing 20 TRDDs in `design/tasks/` were
   grandfathered in place as `planned`.
3. **PRRD init + rules.** Ran `get-prrd.py --init`, set
   `project: ai-maestro-visual-communicator-plugin` and
   `project-id: autonomous`, then seeded 1 GOLDEN (G1.1 — GitHub
   self-identification) and 7 SILVER rules (S2.1–S8.1) faithfully
   transcribing amvcp's established CLAUDE.md conventions (one-skill-per-
   thing, fixed Interaction Design Mode, light+dark, screenshot-testing,
   CPV-as-sole-validator, no-direct-push, runtime-LOC-exemption).
4. **kanban.** Verified `kanban.py` renders a board for the grandfathered
   TRDDs (read-only; no mutation).
5. **README.** Added a `## Dependency` section documenting the runtime
   resolution of the base plugin's pillar scripts.
