# TRDD-5d31a249 — visualize in seconds (fast-path)

**Filename:** `design/tasks/TRDD-20260611_050343+0200-5d31a249-visualize-fast-path.md`
**Tracked in:** this repo (`design/tasks/` is git-tracked)

## User mandate (verbatim intent, 2026-06-11)

> "the visual communication plugin is supposed to visualize anything very fast…
> the skills need to be improved, provided with faster toolings, made working in
> parallel. they should be able to show the user anything in a few seconds."

## Measured baseline (the fleet-workflow render, 2026-06-11)

End-to-end ~10 min for one `.ve-graph` page. Time went to:

1. **Serial reference reading (~60% of wall-clock).** The documented workflow
   (umbrella SKILL → category SKILL → interactive-selection-base (649 ln) →
   graphviz-cookbook (311 ln) → styling-guide (144 ln) + house-example probes) =
   8 reads BEFORE one line of output — and the umbrella says "read it every time".
2. **From-scratch authoring.** ~700 hand-written lines: hero/CSS/DESIGN.md/atoms/
   graph/key/table — although ~80% of it is invariant boilerplate.
3. **A 2-defect debug round-trip (~25%)** — BOTH defects were doc gaps, not logic:
   - **DESIGN.md fence trap:** `parseDesignMd` is fail-fast and REQUIRES the
     embedded `<script type="text/design-md">` payload to open/close with `---`
     fences. NOTHING on the authoring path says so, the failure is a SILENT
     fallback to the built-in palette, and the in-repo house example
     (`reports/…/symphony-vs-amoa-amvcp.html`) itself lacks fences (latent bug —
     its tokens never applied; nobody noticed because page CSS carries fallbacks).
   - **Graphviz `<path>` trap:** `style=rounded` boxes render as `<path>`, but
     every CSS recipe in graphviz-cookbook.md targets `polygon/ellipse/circle`
     only — node fills/strokes/hover silently never apply.

## Plan (4 slices, each independently shippable)

### S1 — QUICKSTART fast-path references (kills the serial-read tax)
One condensed `references/QUICKSTART-<flow>.md` per high-frequency flow, ≤120
lines, containing ONLY the load-bearing contract: page skeleton (designmd → runtime
script order), the FENCED DESIGN.md block, `--ve-accent`/`--ve-sel-text`, atom
stamps, engine-routing one-liner, per-engine defaults, hover/selected mirror rule,
and the 2 traps above. First target: `QUICKSTART-web-diagram.md`. The
`/amvcp-generate-web-diagram` command then points at the QUICKSTART FIRST and at
the deep references only "when the quickstart doesn't cover it".

### S2 — ready-to-fill Graphviz template (kills from-scratch authoring)
`templates/graphviz-diagram.html` (peer of the existing mermaid-flowchart.html):
complete working page — fenced dual-theme DESIGN.md, blueprint-grid CSS with
`path, polygon, ellipse` node selectors + hover/selected mirrors + edge rules +
graph key + hero + footer — with clearly marked `<!-- FILL: … -->` slots (title,
lede, DOT source, optional sections). Authoring becomes a content transplant.
Target: goal→pixels < 60 s for a standard diagram.

### S3 — parallel-read + parallelism rule (made working in parallel)
- Umbrella SKILL "Instructions" + authoring-workflow get a hard rule: batch ALL
  reference/file reads of a generation flow into ONE parallel tool-call message.
- For multi-visual jobs (N diagrams / N pages): one spark agent per artifact in
  parallel — never serial authoring (mirrors the ≤5-files-per-agent budget).
- Verification parallelism: light+dark screenshots taken in the same pass.

### S4 — doc-truth + example fixes (kills the silent-failure class)
- Document the `---` fence requirement EVERYWHERE the embedded block is shown
  (design-tokens SKILL, css-patterns theme section, QUICKSTARTs, templates).
- Fix `reports/…/symphony-vs-amoa-amvcp.html` (add fences) — and grep all
  templates/fixtures for fenceless `text/design-md` blocks.
- graphviz-cookbook.md: add the `<path>` (rounded-box) note to the CSS section +
  fix its recipes to `path, polygon, ellipse`.
- Consider a runtime `console.warn` when the embedded block parse fails (it logs
  today; verify it's loud + add the fence hint to the message).
