A 7-role categorical color map for time-tracking / productivity /
status visualisations: `working`, `meeting`, `break`, `idle`, `focus`,
`review`, `blocked`. Seven roles can't map onto four semantic-state
roles, so the map is a CATEGORICAL ramp built off the active accent
via golden-angle rotation.

## What it does

`amvcpTokens.ROLE_MAPS.activity` declares:

```js
activity: {
  attr: 'data-vc-role',
  categorical: true,
  base: 'accent',
  order: [
    'working', 'meeting', 'break', 'idle',
    'focus', 'review', 'blocked'
  ]
}
```

`renderRoleMapCss('activity', seedAccentHex)` baked-output:

```css
:root {
  --vc-cat-working:  <hue0>;   /* seed accent (chroma-clamped) */
  --vc-cat-meeting:  <hue1>;   /* seed + 137.508° */
  --vc-cat-break:    <hue2>;   /* seed + 275° */
  --vc-cat-idle:     <hue3>;   /* seed + 412° */
  --vc-cat-focus:    <hue4>;
  --vc-cat-review:   <hue5>;
  --vc-cat-blocked:  <hue6>;
}

[data-vc-role="working"] {
  --vc-role-color: var(--vc-cat-working);
  color: var(--vc-role-color);
  background:   color-mix(in srgb, var(--vc-role-color) 12%, var(--vc-color-surface));
  border-color: color-mix(in srgb, var(--vc-role-color) 30%, var(--vc-color-surface));
}
/* … 6 more selectors, one per role … */
```

The 7 hues are generated by `generateCategoricalHues(seedAccentHex, 7)`
— see `references/golden-angle-categorical.md` for the rotation math.

## When to use

This vocabulary is documented for:

- Calendar / day-planner views (each appointment block colored by
  activity type);
- Sprint board "in-progress" lanes (each card carries an activity
  badge);
- Real-time status indicators (a teammate avatar tinted by current
  activity);
- Time-tracking pie charts (each wedge labelled by activity role).

It's NOT a generic state vocabulary — `MUST/IMO/Q/FYI` (the badge map)
is for review severity; `success/warning/danger/info` (the engine
semantic roles) is for outcomes. `activity` is for the in-flight state
of a HUMAN (or autonomous agent acting like one).

## Scaffold to emit

```html
<script>
  // Seed off the page's active accent (the contact sheet does this).
  var accent = getComputedStyle(document.documentElement)
    .getPropertyValue('--vc-color-accent').trim();
  document.head.insertAdjacentHTML('beforeend',
    amvcpTokens.renderRoleMapCss('activity', accent));
</script>

<ul class="vc-activity-list">
  <li data-vc-role="working">10:00 — 11:30 : Coding the deployer</li>
  <li data-vc-role="meeting">11:30 — 12:00 : Standup</li>
  <li data-vc-role="break">12:00 — 13:00 : Lunch</li>
  <li data-vc-role="focus">13:00 — 15:00 : Deep work — review backlog</li>
  <li data-vc-role="blocked">15:00 — 15:30 : Waiting on API key from DevEx</li>
</ul>
```

## Lib functions used

- `amvcpTokens.renderRoleMapCss('activity', seedAccentHex)` →
  `<style>` text block (omit `seedAccentHex` to fall back to the
  Heritage honey `#b8861f`)
- `amvcpTokens.generateCategoricalHues(seed, 7)` — the raw hex array
  if you want to introspect or use the hues directly (e.g. as a chart
  series color array)

## DESIGN.md tokens used

- reads (typical): `colors.<theme>.accent` (passed as `seedAccentHex`)
- reads (via the bg/border mix): `--vc-color-surface` (theme-flips)
- emits (via the role-map CSS): `--vc-cat-working` …
  `--vc-cat-blocked` (one variable per role) + the
  `[data-vc-role="…"]` selectors

## Anti-slop interaction

Like every categorical map built off the accent, no literal hex from
the banned set can sneak in: the seed is supplied by the agent (which
itself has been linted via `lintTokenSet` on the preset), and the
golden-angle rotation moves successive hues far away from any single
banned hue's OKLab radius.

If a CONSUMER hardcodes `[data-vc-role="working"] { background: #22C55E; }`
instead of letting the role-map CSS theme it — that's
slop. The structural fix is to delete the hardcoded override and let
the role-map CSS win (it ships in `ve-component`, so the override
must intentionally beat it).

## Selection / comment / decision-mini contract

Activity chips are inline elements that participate in normal text
selection. A chip's bg / fg / border stays intact under the
`--vc-selection-bg` overlay (opaque colors compose cleanly).

Each chip is a `<button data-vc-copy="<value>">` when rendered inside
the contact sheet's semantic-roles panel — click-to-copy the CSS
variable name (e.g. `var(--vc-cat-working)`) for the designer to
paste into another component.

## Visual verification

Per `skills/amvcp-self-debug-rules/SKILL.md` — render a list of all 7
activity badges under `dev-browser`. Screenshot in **both themes** (R1)
and verify:

1. NO two adjacent badges read as the same color (the golden-angle
   spread guarantees this; if they collide, the seed accent has a hue
   that's symmetric under 137° rotation — rare in practice, but a
   different seed fixes it);
2. all 7 chips remain readable (`amvcpTokens.contrastRatio(fg, bg) >=
   4.5`) in BOTH themes;
3. swapping the page accent via `hotSwap` re-tints all 7 chips
   (re-seed the ramp by re-running `renderRoleMapCss` with the new
   accent — the role-map CSS doesn't auto-react to a hot-swap because
   the hues are baked literal hexes; re-inject the `<style>` block).
